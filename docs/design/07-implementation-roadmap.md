# AiAPS — 实施路线图与开发计划

> 版本：1.0 | 最后更新：2026-03-17

---

## 1. 分阶段实施计划

### 阶段一：基础框架与数据层

```
范围:
  ├── Spring Boot 项目脚手架搭建
  ├── SQL Server 2008 数据库建表
  ├── 基础数据 CRUD (物料/BOM/工艺路线/工作中心/工厂日历)
  ├── 统一响应/异常处理/JWT 认证
  ├── Vue 3 前端脚手架
  └── 基础数据管理页面

技术风险:
  · SQL Server 2008 分页兼容性 → ROW_NUMBER() 方案已验证
  · MyBatis-Plus 对 SQL Server 2008 的支持 → 需自定义 Dialect

交付物:
  · 可运行的前后端项目
  · 完整的基础数据管理功能
  · 数据库初始化脚本
```

### 阶段二：需求管理与库存

```
范围:
  ├── 需求管理 (三种需求来源的录入/导入/管理)
  ├── 库存管理 (多维库存查询/可用量计算)
  ├── 安全库存预警
  ├── 需求汇总看板
  └── 库存看板

技术风险:
  · 库存实时性 → 定时同步 + 事件增量更新结合
  · 安全库存自动生成需求 → Quartz 定时任务 + 手动触发

交付物:
  · 需求管理功能完整可用
  · 库存数据对接方案确认
```

### 阶段三：MRP 引擎（核心）

```
范围:
  ├── MRP 展算引擎核心实现
  │   ├── LLC 低阶码计算
  │   ├── 需求合并策略
  │   ├── 净需求计算
  │   ├── 批量策略 (LFL/FOQ/POQ/EOQ)
  │   ├── 提前期偏移
  │   └── 计划订单生成
  ├── MRP 工作台 UI
  ├── 计划订单审核流程
  ├── 采购建议生成
  ├── 需求-供给追溯 (Pegging)
  └── MRP 异常报告

技术风险:
  · 性能: 10000 条需求 30 秒 → 内存计算 + 批量写入
  · BOM 循环引用检测 → LLC 计算时检测
  · 净变更 MRP 的准确性 → 充分测试

交付物:
  · MRP 引擎可正确运行
  · 计划订单正确生成
  · 性能达标
```

### 阶段四：排产调度引擎（核心）

```
范围:
  ├── 有限产能排产算法
  │   ├── 工序展开
  │   ├── 优先级评分
  │   ├── 时间槽分配
  │   ├── 换产时间优化
  │   └── 冲突检测
  ├── 排产甘特图 (Vue 3 + 甘特图组件)
  │   ├── 产线/订单/物料三种视图
  │   ├── 拖拽移动
  │   ├── 插单
  │   └── 拆分/合并
  ├── 产能负荷分析
  └── 增量重排

技术风险:
  · 甘特图性能 → 虚拟滚动 + 按需渲染
  · 拖拽后级联调整 → 递归算法 + 层数限制
  · 冲突自动解决 → 策略模式可扩展

交付物:
  · 排产引擎可自动排产
  · 甘特图可视化与交互完整
  · 产能分析图表
```

### 阶段五：生产执行与闭环

```
范围:
  ├── 生产报工
  ├── 进度跟踪
  ├── 报工触发重排评估
  ├── Dashboard 看板
  ├── 报表输出
  └── WebSocket 实时推送

交付物:
  · 报工数据驱动排产更新
  · 管理看板
  · 系统闭环运行
```

### 阶段六：优化与对接

```
范围:
  ├── 性能调优 (500 并发压测)
  ├── ERP 系统数据对接
  ├── 钢铁行业专属规则精调
  ├── 用户培训与文档
  └── 上线部署

交付物:
  · 通过压测
  · 对接联调完成
  · 正式上线
```

## 2. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| SQL Server 2008 功能限制 | 中 | 已在设计中规避高版本特性 |
| BOM 数据不完整 | 高 | MRP 运行前数据完整性检查 + 异常报告 |
| 排产算法效果不理想 | 高 | 分阶段验证: 先用简单优先级排序验证流程，再优化算法 |
| 甘特图组件选型 | 中 | 优先评估 DHTMLX Gantt(开源版) 和 Bryntum(商业版) |
| 500 并发性能 | 中 | 读写分离 + Redis 缓存 + 异步计算，阶段六压测验证 |
| 换产时间数据缺失 | 中 | 提供默认值，逐步由车间主任完善数据 |

## 3. 测试策略

### 3.1 单元测试

```
重点测试:
  · MRP 净需求计算逻辑 (各种批量策略)
  · BOM 展开正确性 (多层级/虚拟件/替代物料)
  · 排产时间槽分配算法
  · 冲突检测逻辑
  · 提前期计算
```

### 3.2 集成测试场景

```
场景1: MTO 全流程
  输入: 1份合同(3行, 3种管材), 有部分库存
  预期: MRP 正确计算净需求, 生成计划订单, 排产到对应产线

场景2: 多来源混合排产
  输入: 5份 MTO + 3份 MTS + 2个安全库存触发
  预期: MTO 优先排产, MTS 填缝隙, SSK 最后

场景3: 插单
  输入: 已排满 3 天的焊管产线, 紧急插入 1 个高优先级订单
  预期: 插单成功, 低优先级任务后移, 冲突正确报告

场景4: 设备故障
  输入: 某产线突然停机 4 小时
  预期: 增量重排将受影响任务重新分配或后延

场景5: 大批量 MRP
  输入: 10,000 条需求行
  预期: ≤ 30 秒完成, 结果正确
```

### 3.3 性能测试

```
压测工具: JMeter / Gatling

场景:
  · 500 并发用户登录
  · 500 并发查询甘特图数据
  · 200 并发提交报工
  · 50 并发执行拖拽调整
  · 5 并发启动 MRP 运算 (应排队执行)
```

## 4. 部署架构

```
生产环境部署 (500并发):

┌──────────────┐
│   Nginx      │  ← 静态资源 + 反向代理 + 负载均衡
│   (前端+LB)  │
└──────┬───────┘
       │
┌──────┼──────────────────────┐
│      ▼                      │
│  ┌────────┐   ┌────────┐   │
│  │ App-1  │   │ App-2  │   │ ← Spring Boot 应用 (2~3 实例)
│  │ :8080  │   │ :8080  │   │    每实例 -Xmx2g
│  └───┬────┘   └───┬────┘   │
│      │            │        │
│  ┌───┴────────────┴────┐   │
│  │      Redis 6.x      │   │ ← 缓存 + 会话
│  │      (主从)          │   │
│  └─────────────────────┘   │
│                             │
└──────────────┬──────────────┘
               │
       ┌───────┴───────┐
       │ SQL Server    │  ← 主库(读写) + 镜像/日志传送(只读)
       │ 2008          │
       └───────────────┘

硬件建议:
  · 应用服务器: 2~3 台, 各 4核/8G
  · Redis: 1主1从, 2核/4G
  · SQL Server: 1主1备, 8核/32G, SSD
  · Nginx: 复用应用服务器
```
