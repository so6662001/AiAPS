## 0. 设计目标

```

┌──────────────────────────────────────────────────────────────┐
│  修改三原则                                                   │
│                                                              │
│  1. 改之前 — 看清影响                                         │
```

## 1. 计划修改 (MRP 计划订单修改)

### 1.1 计划修改的触发场景

| 场景 | 触发 | 修改动作 |
|------|------|---------|
| 客户改单 | 客户变更合同数量/交期/规格 | 需求变更 → 联动修改计划订单 |
| 客户取消 | 客户取消合同行 | 取消关联计划订单 + 释放已分配资源 |
| 客户加单 | 同合同追加数量 | 修改需求数量 → MRP 净变更 or 手动追加计划 |
| 库存变动 | 盘点差异 / 紧急出库 | 重新计算净需求 → 调整计划订单量 |
| 采购变更 | 供应商延期/部分到货 | 调整计划订单开始日期 / 拆分计划 |
| 工艺变更 | 工艺路线更新 / BOM 修改 | 重新计算用量 → 调整子层计划 |
| 计划员判断 | 经验性调整(合并小批/平衡产能) | 手动修改数量/日期/合并/拆分 |

### 1.2 计划订单支持的修改操作

```
┌──────────────────────────────────────────────────────────────────┐
│                  计划订单修改操作全集                              │

│  │  · 修改日期      开始日/完成日前后移动                      │ │
│  │  · 修改类型      MFG(自制) ↔ PUR(采购) ↔ SUB(委外)         │ │
│  │  · 修改优先级    紧急度调整                                 │ │
│  │  · 锁定/解锁    锁定后不被 MRP 重算覆盖                    │ │
│  │  · 确认          PLANNED → CONFIRMED (可进入排产)          │ │
│  │  · 取消          释放资源, 取消关联子层计划                  │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                                                                  │
│  ┌─ 拆分/合并 ─────────────────────────────────────────────────┐│
│  │  · 拆分计划      1个50T → 拆为 30T + 20T (不同日期/类型)   ││
│  │  · 合并计划      多个同物料计划 → 合并为1个 (取最早交期)    ││
│  └─────────────────────────────────────────────────────────────┘│
│                                                                  │
│  ┌─ 批量操作 ─────────────────────────────────────────────────┐ │
│  │  · 批量确认      选中多条 → 一键确认                       │ │
│  │  · 批量取消      选中多条 → 一键取消                       │ │
│  │  · 批量改日期    选中多条 → 统一推迟/提前 N 天              │ │
│  │  · 批量转排产    选中多条 → 一键创建排产任务                │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                                                                  │
│  ┌─ 联动操作 ─────────────────────────────────────────────────┐ │
│  │  · 需求变更联动  需求量变 → 自动调整计划量 → 调整子层计划   │ │
│  │  · 重新展算      对修改过的计划触发局部 MRP 重算             │ │
│  └─────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

## 2. 排产修改 (APS 排产计划修改)

```
│                 │ 3. 方案A: 转移到替代产线                           │
```

### 2.3 排产修改的影响分析引擎

```java
/**
 * 排产修改影响分析引擎
 * 在执行修改前，计算修改会产生的所有影响
 */
public class ScheduleChangeImpactAnalyzer {

    public static class ChangeImpact {
        // 时间影响
        private Map<Long, TimeChange> timeChanges;        // 受影响任务的时间变化
        // 交期影响
        private List<DueDateRisk> dueDateRisks;            // 交期可能受影响的订单
        // 产能影响
        private Map<Long, LoadChange> loadChanges;         // 工作中心负荷变化
        // 原料影响
        private List<MaterialImpact> materialImpacts;      // 原料供给缺口
        // 模具影响
        private List<MoldImpact> moldImpacts;              // 模具寿命/换模影响
        // 冲突
        private List<Conflict> newConflicts;                // 修改后新产生的冲突
        // 总体评估
        private RiskLevel overallRisk;                      // HIGH/MEDIUM/LOW/NONE
    }

    /**
     * 分析"移动排产任务"的影响
     */
    public ChangeImpact analyzeMove(Long scheduleId, 
                                     DateTime newStart, Long newWcId) {
        ChangeImpact impact = new ChangeImpact();
        
        ScheduleTask task = scheduleMapper.selectById(scheduleId);
        DateTime newEnd = calcNewEnd(task, newStart, newWcId);
        
        // 1. 级联时间影响: 后续任务是否需要推移
        List<ScheduleTask> affected = findCascadeAffected(
            task, newStart, newEnd, newWcId);
        for (ScheduleTask t : affected) {
            impact.addTimeChange(t.getScheduleId(), 
                t.getScheduleStart(), calcCascadedStart(t));
        }
        
        // 2. 交期风险: 修改后是否有订单的交期会被突破
        for (ScheduleTask t : affected) {
            DateTime newFinish = calcCascadedEnd(t);
            if (t.getDueDate() != null && newFinish.isAfter(t.getDueDate())) {
                impact.addDueDateRisk(new DueDateRisk(
                    t.getScheduleId(), t.getSourceDemandNo(),
                    t.getDueDate(), newFinish,
                    Days.daysBetween(t.getDueDate(), newFinish).getDays()
                ));
            }
        }
        
        // 3. 产能负荷变化
        if (newWcId != null && !newWcId.equals(task.getWcId())) {
            impact.addLoadChange(task.getWcId(), /* 原产线减少 */);
            impact.addLoadChange(newWcId, /* 新产线增加 */);
        }
        
        // 4. 原料影响(跨日期移动可能影响原料到位时间匹配)
        checkMaterialAvailability(task, newStart, impact);
        
        // 5. 模具影响(跨产线时模具可能不同)
        if (newWcId != null && !newWcId.equals(task.getWcId())) {
            checkMoldAvailability(task, newWcId, impact);
        }
        
        // 6. 冲突检测
        impact.setNewConflicts(conflictDetector.detectAfterChange(
            task, newStart, newEnd, newWcId));
        
        // 7. 总体风险评估
        impact.setOverallRisk(assessRisk(impact));
        
        return impact;
    }
}
```
