# AiAPS — 分剪业务全链路数据走查实例

> 版本：1.0 | 最后更新：2026-03-17
>
> 以一个真实的分剪场景完整走查数据在每一张表中的呈现方式。

---

## 0. 业务场景描述

```
输入:
  母卷: 热轧卷 2.5×1500×C, Q235B, 鞍钢, 卷号HRC-2026-0088, 重量20T

操作:
  分剪(纵切), 两刀分三条

产出:
  子卷1: 2.5×300  Q235B — 1卷,  约4T    → 直接销售给客户A
  子卷2: 2.5×600  Q235B — 2卷,  共约16T → 用于后续制管
  边丝:  每边5mm + 2道锯缝共4mm = 14mm  → 废料约0.19T

  合计产出: 4 + 16 = 20T (余: 边丝+锯缝废料约0.19T)
  实际利用率: (4+16) / 20 = 99.1%
```

## 3. 排产链路

### 3.1 套裁方案 (aps_nesting_plan + aps_nesting_detail)

```

│nesting_id│nesting_no│type  │mat_id│grade │coil_no   │width │thick │weight│
│          │          │      │(母卷)│_code │          │      │      │      │
├──────────┼──────────┼──────┼──────┼──────┼──────────┼──────┼──────┼──────┤
│ 7001     │NEST-0088 │SLIT  │5001  │Q235B │HRC-2026- │1500  │2.500 │20.000│
│          │          │      │      │      │0088      │      │      │      │
└──────────┴──────────┴──────┴──────┴──────┴──────────┴──────┴──────┴──────┘

补充字段:
  source_stock_id = 8001
  source_origin_code = '鞍钢'   ← 母卷产地(从库存继承)
  edge_trim = 5.0 (每边5mm)
  kerf_width = 2.0 (锯缝宽度)
  slit_count = 3 (分3条)
  utilization_pct = 99.07
  waste_weight = 0.186  (边丝+锯缝)

分条计算:
  可用宽度 = 1500 - 5×2(两侧边丝) = 1490mm
  分条: 300 + 600 + 600 = 1500mm
  锯缝: 2刀 × 2mm = 4mm
  实际: 300 + 600 + 600 + 4(锯缝) + 10(边丝) = 1514mm
  但母卷实际1500mm → 边丝略窄: (1500 - 300 - 600 - 600 - 4) / 2 = -2mm
  → 实际边丝每边仅(1500-1504)/2 → 调整: 无边丝或极少
  
  更合理的分条:
  1500 = 300×1 + 597×2 + 2×2(锯缝) + 2×1(最小边丝)
  产出: 300×1 + 597×2 = 1494mm + 锯缝4mm + 边丝2mm = 1500mm ✓

=== aps_nesting_detail (明细) ===

│        │        │    │(带钢 │      │      │(1卷) │      │      │          │
│        │        │    │300)  │      │      │      │      │      │          │
├────────┼────────┼────┼──────┼──────┼──────┼──────┼──────┼──────┼──────────┤
│ 7102   │7001    │2   │5102  │600.0 │2.500 │2     │7.920 │15.840│PRODUCT   │
│        │        │    │(带钢 │      │      │(2卷) │(单卷)│(2卷) │          │
│        │        │    │600)  │      │      │      │      │      │          │
├────────┼────────┼────┼──────┼──────┼──────┼──────┼──────┼──────┼──────────┤
│ 7103   │7001    │3   │NULL  │—    │2.500 │—    │0.200 │0.200 │WASTE     │
│        │        │    │(无)  │      │      │      │      │(边丝)│(废料)    │
└────────┴────────┴────┴──────┴──────┴──────┴──────┴──────┴──────┴──────────┘

补充字段:
  行7101: demand_line_id = 2001 (关联客户A需求)
          schedule_id = (分剪排产后关联, 见下)
  
  行7102: demand_line_id = 2002 (关联制管需求)
          schedule_id = (分剪排产后关联)

重量计算(按宽度占比):
  300/1500 × 20T = 4.000T (理论)
  实际考虑边丝: 300/(300+600+600) × (20-0.2) = 300/1500 × 19.8 = 3.960T
  
  600/1500 × 2卷 = (600/1500 × 19.8) × 2 = 7.920 × 2 = 15.840T
  
  合计: 3.960 + 15.840 + 0.200 = 20.000T ✓
```

## 7. 数据完整性校验规则

```
分剪场景的数据校验:

1. 重量守恒:
   母卷投入重量 = Σ(子卷产出重量) + 废料重量
   20.000 = 3.960 + 7.920 + 7.920 + 0.200 = 20.000 ✓

2. 宽度守恒:
   母卷宽度 ≥ Σ(子卷宽度) + 锯缝 + 边丝
   1500 ≥ 300 + 600 + 600 + 4(锯缝) = 1504mm
   (差额-4mm说明此方案无边丝或微边丝, 实际可行)

3. 材质一致性:
   所有子卷的 grade_code = 母卷的 grade_code ✓
   产地同理: origin_code = 母卷的 origin_code ✓

4. 厚度一致性:
   所有子卷的 thickness = 母卷的 thickness ✓

5. 追溯完整性:
   每条子卷库存都能追溯到:
   · 套裁方案 nesting_id → 母卷 coil_no → 供应商/炉号
   · 排产单 schedule_id → 需求单 demand_line_id → 客户订单
```
