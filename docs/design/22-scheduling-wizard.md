# AiAPS — 排产向导：操作流程优化设计

> 版本：1.0 | 最后更新：2026-03-17
>
> 针对现场反馈"排产操作步骤太多、太复杂"的问题，对现有 16 步排产流程做
> 交互重构，目标：**常规排产 3 步完成、点击数减少 70%、手填字段减少 80%**。
> 充分复用系统已有能力（MRP 计划订单、规格推算引擎、智能配料、套料、
> 模具分组、排产评分），让"系统先算、人来确认"取代"人来填、系统记账"。

---

## 0. 问题诊断：现状为什么"复杂"

### 0.1 现状操作流程（用户原话还原）

```
┌─ 阶段一：选订单（弹窗1）────────────────────────────────────────┐
│  1. 选择成品品类                                                 │
│  2. 选择工艺                                                     │
│  3. 输入需要查找的规格                                           │
│  4. 查询                                                         │
│  5. 勾选需要生产的订单                                           │
│  6. 下一步                                                       │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌─ 阶段二：配原料、算产出（弹窗2，上下两块表格）──────────────────┐
│  7.  修改成品明细（材质 + 带*号必填）                            │
│  8.  确认成品                                                    │
│  9.  原材料输入规格型号                                          │
│  10. 点击确认                                                    │
│  11. 填写投入的数量与重量                                        │
│  12. 添加原料                                                    │
│  13. 计算产出量                                                  │
│  14. 修改本次排产数量、重量                                      │
│  15. 确认产出                                                    │
│  16. 保存                                                        │
└────────────────────────────────────────────────────────────────┘

合计：16 步，2 个弹窗，4 处"确认/计算"中间动作，9+ 个手填字段。
```

### 0.2 痛点归类（5 类）

| # | 痛点 | 表现 | 根因 |
|---|------|------|------|
| P1 | **筛选链路太长** | 品类→工艺→规格→查询，4 步才看到订单 | 把"过滤器"当成"必经流程"，串行强制 |
| P2 | **手填字段多** | 材质、规格型号、投入数量/重量都靠人输 | 系统已有 BOM/库存/推算能力却没前置 |
| P3 | **"确认/计算"动作冗余** | 确认成品、点确认、计算产出、确认产出 4 次 | 每个子表格各自一套"确认"按钮，未串成流水线 |
| P4 | **缺少默认值与推荐** | 原料选哪卷、产线、模具全靠人决定 | 智能配料/排产评分能力没接进 UI |
| P5 | **没有即时反馈** | 算完产出才知道成材率/缺料/超期 | 校验滞后到"保存"才暴露，返工成本高 |

### 0.3 设计目标（量化）

```
┌──────────────────────────────────────────────────────────────┐
│  指标             现状        目标         手段                │
│  ───────────────────────────────────────────────────────────  │
│  操作步骤         16 步       3 步(常规)   合并+自动化         │
│  弹窗数           2 个        0 个(整页)   单页向导式          │
│  手填字段         9+          ≤2           系统预填+推荐        │
│  "确认"中间动作   4 次        1 次(末尾)   流水线，边走边算    │
│  完成一单耗时     ~3 min      ~30 s        默认值 + 批量        │
│  错误暴露时机     保存时      实时         即时校验/影响预览    │
└──────────────────────────────────────────────────────────────┘
```

## 1. 总体设计理念

```
核心理念：把"人填表"变成"人审单"

  现状（命令式）：人告诉系统每一个字段 → 系统被动记录
  优化（声明式）：人选目标 + 给约束 → 系统主动算方案 → 人审核确认

  ┌─────────────────────────────────────────────────────────────┐
  │  三条主线                                                    │
  │                                                             │
  │  1. 能不点就不点 —— 合并步骤                                 │
  │     · 筛选器并排常驻，不再"品类→工艺→规格→查询"串行          │
  │     · 选成品的同时，原料/产出在右侧实时联动算出               │
  │                                                             │
  │  2. 能默认就默认 —— 系统预填                                 │
  │     · 材质/规格 来自需求行 + BOM，自动带出                   │
  │     · 原料卷 来自智能配料（库存可用 + 7级匹配 + 窜料控制）    │
  │     · 产线/模具 来自排产评分（成本/效率策略）                 │
  │     · 投入量/产出量 来自规格推算引擎（成材率反算）            │
  │                                                             │
  │  3. 能预览就预览 —— 实时反馈                                 │
  │     · 成材率、缺料、超期、合同冲突，边选边亮                  │
  │     · 右侧迷你甘特图实时显示排在哪、占多久                    │
  │     · 保存前给"影响预览"，确认即落地                          │
  │                                                             │
  └─────────────────────────────────────────────────────────────┘
```

## 2. 优化后流程：3 步排产向导

### 2.1 流程总览

```
┌─ Step 1 选什么生产 ─┐   ┌─ Step 2 怎么生产 ──┐   ┌─ Step 3 排在哪/确认 ┐
│ 一屏筛选 + 勾订单    │ → │ 系统已配好原料+产出 │ → │ 系统已排好产线+时间  │
│ (筛选器并排，非串行) │   │ 人只审核/微调      │   │ 人审影响预览，一键存 │
└─────────────────────┘   └────────────────────┘   └─────────────────────┘
     原 1~6 步                  原 7~15 步                  原 16 步 + 新增
     合并为 1 步                合并为 1 步(默认全自动)     合并为 1 步(含智能排产)

  极简路径（80% 常规单）：
    勾订单 → [下一步] → 看一眼系统配好的方案 → [下一步] → [确认排产]
    = 4 次点击，0 次手填
```

### 2.2 与现状步骤的逐项映射

| 现状步骤 | 优化后归属 | 处理方式 |
|---------|-----------|---------|
| 1 选品类 / 2 选工艺 / 3 输规格 / 4 查询 | Step 1 筛选区 | 改为**并排常驻筛选器**，输入即查（防抖），去掉"查询"按钮 |
| 5 勾订单 | Step 1 列表 | 保留勾选；支持"全选本页/按合同分组选" |
| 6 下一步 | Step 1 → 2 | 保留 |
| 7 改成品明细（材质+必填） | Step 2 成品卡 | 材质/规格**自动带出**需求行；带*项预填 BOM 默认值，仅缺失时高亮 |
| 8 确认成品 | 取消 | 进入 Step 2 即视为"成品已确认"，无需单独点 |
| 9 原料输规格 / 10 确认 | Step 2 原料卡 | **智能配料自动推荐**原料卷，免输入；可换料 |
| 11 填投入数量/重量 | Step 2 原料卡 | 由规格推算引擎**反算预填**，可微调 |
| 12 添加原料 | Step 2 原料卡 | 自动加入；多原料时自动配比 |
| 13 计算产出量 | 取消（实时） | **边配边算**，无需手动点"计算" |
| 14 改本次排产数量/重量 | Step 2 产出卡 | 默认=订单需求量；可改，自动联动原料用量 |
| 15 确认产出 | 取消 | 实时显示，进入 Step 3 即确认 |
| 16 保存 | Step 3 确认排产 | 升级为"含产线/时间的排产确认 + 影响预览" |

> 结论：**4 个"确认/计算"动作全部取消或合并**（8/10/13/15 → 实时化），
> 2 个弹窗合并为 1 个整页向导，9+ 手填字段降到"通常 0、最多 2"。

## 3. Step 1 — 选什么生产（合并原 1~6 步）

### 3.1 界面布局

```
┌──────────────────────────────────────────────────────────────────────┐
│  新建排产                                    ① 选订单 → ② 配方案 → ③ 排产│
├──────────────────────────────────────────────────────────────────────┤
│  ▸ 来源  [● 计划订单]  [○ 需求订单]  [○ 原料驱动]   ← 默认计划订单     │
│                                                                        │
│  品类[管材▾] 工艺[开平▾] 规格[输入即查 4.0*1500   ] 材质[全部▾]        │
│  交期[本周▾] 合同号[          ] [⚙更多筛选]      [↻重置]               │
│   ↑ 并排常驻，输入即过滤（300ms 防抖），不再有"查询"按钮               │
├──────────────────────────────────────────────────────────────────────┤
│ ☑ 合同号        客户      品名规格      材质  数量   重量    交期  缺料 │
│ ☑ HT2026-0318  通源大兴  焊管4.0*Φ89   Q345B 50支  10.5T  03-22  ●足  │
│ ☑ HT2026-0318  通源大兴  焊管4.2*Φ89   Q345B 30支  8.47T  03-22  ●足  │
│ ☐ HT2026-0319  广汇钢构  开平4.0*1500  Q235B 20T   20T    03-25  ▲缺  │
│ ☐ HT2026-0320  ...                                                     │
├──────────────────────────────────────────────────────────────────────┤
│  已选 2 行 · 合计 18.97T   [按合同分组]   [合并套料↗]      [下一步 →]  │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 关键交互优化

```
① 筛选器并排常驻、输入即查
   · 取消"查询"按钮：规格/合同号输入框 300ms 防抖自动过滤
   · 品类/工艺/材质 改为下拉多选，选完立即生效
   · 记忆上次筛选条件（按用户），打开即定位常用品类

② 列表直接给出"决策信息"，避免进下一步才发现问题
   · 缺料列：●足(绿) / ▲缺(黄) / ✕无(红) —— 来自库存可用量实时核对
   · 交期列：临期红色高亮，逾期加⚠
   · 同合同行自动相邻分组，便于一次勾完

③ 选订单后的智能动作
   · [按合同分组]：一键勾选同合同所有行（常见：一个合同多规格一起排）
   · [合并套料↗]：多行同原料时跳套料(见 20-multi-demand-nesting)，
     套料结果回填为排产对象（开平/分剪场景利用率↑）

④ 来源切换（覆盖三种生产驱动，见 01-system-overview）
   · 计划订单（默认）：MRP 已算好净需求，最省事
   · 需求订单：直接从合同行起排（未跑 MRP 时）
   · 原料驱动：先有料后反推可产成品（行情买料场景）
```

## 4. Step 2 — 怎么生产（合并原 7~15 步，默认全自动）

> 这是优化幅度最大的一步。原来 9 步（7~15）的手工配料 + 多次确认/计算，
> 改为**进入即由系统配好方案**，用户默认只需"看一眼"。

### 4.1 界面布局：左成品 / 中原料 / 右产出，三栏实时联动

```
┌──────────────────────────────────────────────────────────────────────┐
│  配方案（系统已自动配料，可微调）            ① → ●② 配方案 → ③         │
├──────────────────────────────────────────────────────────────────────┤
│ 成品(来自订单，已带出) │ 投入原料(智能配料推荐) │ 本次产出(实时反算)    │
│ ─────────────────────  │ ────────────────────── │ ──────────────────── │
│ 焊管 Q345B 4.0×Φ89     │ ✓带钢 Q345B 4.0×305     │ 焊管 4.0×Φ89×6000    │
│ 长 6000  合同 HT..0318 │   宝钢 卷号 R2026-0156  │ 数量 50 支            │
│ 需求 50支 / 10.5T      │   可用 24T  [换料▾]     │ 重量 10.5T           │
│                        │   投入 11.05T (反算)    │ ──────────────────── │
│ * 材质 Q345B  ✓已带    │ ─────────────────────  │ 成材率 95.0% ●优     │
│ * 规格 4.0×Φ89 ✓已带   │ + 添加原料(可选)        │ 损耗 0.55T (边丝)    │
│ 工艺 制管  模具 Φ89-01 │                        │ 副产/废料 自动入账   │
├──────────────────────────────────────────────────────────────────────┤
│ ⚡ 系统已按"库存可用+材质匹配+合同窜料控制"自动选料，成材率 95% 达标   │
│   [全部采用系统方案]            [逐项展开微调]            [下一步 →]   │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 自动化能力来源（复用现有引擎，不重复造轮子）

| 自动项 | 复用模块 | 文档 |
|--------|---------|------|
| 成品材质/规格带出 | 需求行 + 品类BOM | 03-mrp-engine §1 |
| 原料规格自动推算 | 规格推算引擎（方管→带钢宽=周长展开） | 03-mrp-engine §4 / 08 §3 |
| 原料卷智能选取 | 智能配料：库存可用 + 7级材质/产地匹配 + 客户偏好 | 13-grade-origin-substitute |
| 窜料/合同控制 | 合同号贯穿 + 窜料策略校验 | 17-length-contract-mixcontrol |
| 投入量↔产出量 | 成材率反算（双向联动） | 16-execution-fullchain §2 |
| 换料建议 | 上料智能调单（换料成本 vs 调单成本） | 15-cost-simulate-smartswap §3 |
| 模具选取/换模 | 模具寿命 + 换模矩阵 | 09-mold-substitute-flow |

### 4.3 实时联动规则（取消"计算/确认"按钮的关键）

```
联动 1：改产出数量 → 自动反算原料投入
   用户把"本次产出"从 50支 改为 30支
   → 系统按成材率即时反算原料投入 11.05T → 6.63T
   → 无需点"计算产出量"

联动 2：换原料卷 → 自动校验 + 重算成材率
   用户点[换料▾]选了另一卷（不同产地/批次）
   → 即时校验材质等级是否达标（不达标黄字提示）
   → 即时重算成材率与损耗
   → 触发窜料控制：跨合同用料给⚠并要求确认

联动 3：多原料配比 → 自动分摊
   添加第 2 卷原料 → 按可用量/优先级自动分摊投入量，保证总投入守恒

校验前置（错误不再憋到保存）：
   · 缺料：投入量 > 库存可用 → 红字 + [去补料]入口(见 12)
   · 超规：产出长度/规格超工艺能力 → 拦截并提示
   · 成材率异常：低于品类基准线 → 黄字预警（仍可继续）
```

### 4.4 "微调"渐进式展开（默认收起，高级才展开）

```
默认态：只显示一行结论 + [全部采用系统方案]（80% 用户点这个就走）

展开态（点[逐项展开微调]）才显示：
   · 每卷原料的卷号/批次/可用量，可手动换、改投入
   · 产出数量/重量手填覆盖
   · 模具更换、副产品流向标注

—— 把"复杂"留给需要的人，把"简单"给大多数人
```

## 5. Step 3 — 排在哪 / 确认（升级原 16 步"保存"）

> 原来第 16 步只是"保存"，并不决定排在哪条线、什么时间。优化后把
> **有限产能排产**接进来：系统排好产线与时间，用户审"影响预览"后一键落地。

### 5.1 界面布局

```
┌──────────────────────────────────────────────────────────────────────┐
│  确认排产（系统已排好产线与时间）            ① → ② → ●③ 排产          │
├──────────────────────────────────────────────────────────────────────┤
│  策略  [● 效率优先] [○ 成本优先] [○ 交期优先] [○ 均衡]  ← 默认效率    │
│                                                                        │
│  ┌─ 系统排产建议 ───────────────────────────────────────────────┐    │
│  │ 产线  制管线 #1   开始 03-21 08:00  结束 03-22 16:00          │    │
│  │ 模具  Φ89-01（同壁厚连排，免换模）  班次 白班×2               │    │
│  │ 评分  92 分（产能利用 88% · 换模 0 次 · 交期满足 ✓）          │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                        │
│  ┌─ 迷你甘特（排在哪一目了然）─────────────────────────────────┐     │
│  │ 制管#1 |████ 本单 ████|░已排░|                              │     │
│  │ 制管#2 |░░已排░░|        空闲                                │     │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                        │
│  ⚠ 影响预览：占用制管#1 白班 → HT..0320 后延 2h（仍满足交期）         │
├──────────────────────────────────────────────────────────────────────┤
│  [换产线/时间]   [What-If 模拟↗]      [上一步]      [✓ 确认排产]      │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 排产智能与影响预览

```
① 系统自动排（复用 04-scheduling-engine + 15-cost-simulate）
   · 按所选策略给出产线/模具/起止时间 + 评分
   · 同壁厚/同模具自动连排，减少换模（见 09）

② 影响预览（落地前看清后果，见 11-plan-schedule-modification）
   · 本单插入后，受影响的其他排产单（后延/前移）
   · 交期是否仍满足（满足✓ / 风险⚠ / 冲突✕）
   · 产能利用率变化

③ 兜底手动
   · [换产线/时间]：下拉换线，迷你甘特实时刷新评分
   · [What-If 模拟↗]：进沙盒推演多方案对比，确认才应用
```

### 5.3 一次确认，全链路落地

```
点[✓ 确认排产]后，系统自动完成（原来要人记的账，系统记）：
   · 生成排产单（草稿→已确认）
   · 锁定/预留原料卷（库存预占）
   · 生成领料预约（合同号贯穿）
   · 写入甘特图 + 排产列表
   · 多选订单时批量生成，并保持合同分组

完成后弹出"轻提示"：已排产 2 单 / 18.97T
   [查看甘特] [继续排下一批] [完成]
```

## 6. 批量与效率增强

```
┌─ 批量排产（多订单一次走完）──────────────────────────────────┐
│  Step 1 勾多行 → Step 2 系统批量配料（逐行折叠，异常行置顶）   │
│  → Step 3 系统批量排产 → 一键确认全部                          │
│  仅"异常行"（缺料/成材率低/冲突）需人介入，正常行自动通过       │
└──────────────────────────────────────────────────────────────┘

┌─ 模板与一键复用 ─────────────────────────────────────────────┐
│  · "另存为排产模板"：常排品类/工艺/策略一键带入                │
│  · 历史相似单"照此再排一单"：复制方案改数量即可                │
└──────────────────────────────────────────────────────────────┘

┌─ 键盘流（熟练工提速）────────────────────────────────────────┐
│  空格 勾选 · Enter 下一步 · Ctrl+Enter 确认排产 · Esc 返回      │
│  /  聚焦筛选框 · A 全部采用系统方案                            │
└──────────────────────────────────────────────────────────────┘
```

## 7. 后端 API 设计（支撑"系统先算"）

```
# ═══ Step 1 选订单 ═══
GET  /api/v1/schedule/wizard/candidates      # 待排订单（计划/需求/原料驱动）
     入参: source, category, process, spec, grade, dueRange, contractNo
     返回: 列表 + 每行库存可用/缺料标记/交期风险

# ═══ Step 2 自动配方案（一次返回成品+原料+产出） ═══
POST /api/v1/schedule/wizard/auto-plan
     入参: { orderIds:[...] }
     返回: 每单 {
       product:{grade,spec,qty,weight},           # 成品(带出)
       materials:[{resNo,grade,origin,available,issueWeight}],  # 智能配料
       output:{qty,weight,yieldRate,scrap},        # 实时反算产出
       warnings:[shortage|mix|yield...]            # 前置校验
     }
POST /api/v1/schedule/wizard/recalc           # 微调后重算(改产出/换料/配比)
GET  /api/v1/schedule/wizard/swap-options      # 换料候选(智能调单)

# ═══ Step 3 自动排产 + 影响预览 ═══
POST /api/v1/schedule/wizard/auto-sequence
     入参: { plans:[...], strategy: efficiency|cost|due|balance }
     返回: { line, mold, start, end, score, gantt, impact:[...] }
POST /api/v1/schedule/wizard/commit            # 一次确认→生成排产单+预占库存+领料预约
```

> 说明：`auto-plan` / `auto-sequence` 是新增的"编排型"接口，内部聚合
> 既有 MrpEngineService / SpecCalculationEngine / 智能配料 / ScheduleEngineService /
> ScheduleScorerService，对前端只暴露"一次调用拿到整套方案"，是步骤合并的关键。

## 8. 兼容与回退

```
· 保留旧版"逐步填写"入口（高级/特殊单），向导覆盖 80% 常规场景
· 向导每步可"上一步"回改，不丢已填数据
· 系统方案全程可被人工覆盖（声明式 → 命令式可降级）
· 灰度：先在单一品类/单一产线试点，对比"耗时/点击数/返工率"再全量
```
